# Resale Ops в ChatGPT Project

Этот вариант позволяет использовать общий workflow и ID облачной очереди в новых
чатах одного ChatGPT Project. Локальная установка skill через `npx` здесь не нужна.
Это настройка проекта с инструкциями и источником workflow, а не установка плагина из каталога.

## 1. Создайте отдельный проект

Создайте ChatGPT Project для продажи вещей. Дальнейшие чаты начинайте внутри него:
инструкции и источники проекта доступны его чатам. Не рассчитывайте на перенос
файлов или доступа в чаты за пределами проекта.

## 2. Выберите источник workflow

### Вариант A: ссылка на GitHub

Можно обойтись без загрузки файлов. В шаблоне инструкций по умолчанию указан
режим **GitHub link** и прямая ссылка на skill:

https://github.com/mkayander/resale-ops/blob/main/skills/resale-ops/SKILL.md

Инструкции требуют в каждом новом чате перед работой прочитать SKILL.md и нужные
справочные файлы по его относительным ссылкам. Агенту нужен инструмент, способный
открывать эти страницы. При необходимости используйте Raw для самого Markdown.
Страница skills.sh, поисковый фрагмент или навигация GitHub не заменяют текст skill.

**Это может работать, но загрузка по ссылке не гарантирована в каждом чате.**
Если файл или необходимый reference недоступен, агент должен назвать проблему
и попросить загрузить полный workflow. Он не должен заявлять, что skill прочитан.
Сама ссылка не устанавливает skill и не предоставляет Google-инструменты.

### Вариант B: загруженный снимок — надёжнее при недоступных ссылках

Загрузите `resale-ops-project-context.md`, который объединяет SKILL.md, все
references и лицензию. В шаблоне поменяйте строку `Default source mode` на
`uploaded snapshot`. Выберите один основной источник, чтобы не смешивать версии.

Файл можно собрать из скачанного репозитория (Python 3.10+, без зависимостей):

```sh
python scripts/build_project_context.py --output /chosen/path/resale-ops-project-context.md
```

Либо попросите агента с доступом к репозиторию собрать его. Вручную можно загрузить
SKILL.md и все Markdown-файлы из `skills/resale-ops/references/`, затем указать
эти имена в инструкциях и проверить чтение. Одного SKILL.md недостаточно.
ZIP сам по себе не считается прочитанным workflow: проверьте доступ к содержимому.

## 3. Подключите Drive и Sheets

Подключите Google-сервисы через доступные настройки ChatGPT. Нужны реальные
возможности чтения фото, чтения/записи файлов и изменения строк таблицы.
ID и ссылки не предоставляют доступ. Конкретные действия зависят от доступных
подключений, аккаунта и настроек организации. Наличие источника Drive или поиска
по нему не доказывает доступность записи.

## 4. Вставьте шаблон инструкций проекта

Откройте [готовый шаблон](../skills/resale-ops/references/chatgpt-project-instructions.md).
Скопируйте его целиком в инструкции проекта. Замените REPLACE реальными ID,
ссылками и городом; оставьте язык пустым, чтобы агент следовал языку разговора.
Если очереди ещё нет, сначала создайте её по [стартовой инструкции](../GETTING-STARTED.md),
затем перенесите возвращённые ID. Не вставляйте пароли, ключи и cookies.

Тот же JSON можно хранить как `Resale/.resale-locations.json` в приватной папке.
Не загружайте заполненный конфиг в публичный GitHub. Права доступа к проекту
определяют, кто ещё может видеть его инструкции и файлы.

## 5. Проверьте новый чат

В новом чате **этого проекта** отправьте:

```text
Проверь настройку Resale Ops. Прочитай workflow из выбранного источника и назови прочитанные
разделы о ценах, облачной очереди и фото. Возьми ID из инструкций проекта.
Прочитай мою папку queue и заголовки вкладки Queue; ничего не меняй.
Сообщи, доступны ли запись файлов, изменение строк и обработка фото.
Если нет доступа к workflow, его references или облаку, явно укажи, чего не хватает.
```

Проверьте ссылки, возвращённые агентом. Для проверки записи отдельно разрешите
создать одну тестовую вещь с синтетическими данными и строкой `draft`, проверьте
результат в Drive и Sheets. Не используйте реальные личные фото для теста.
Отсутствие инструментов обработки фото означает, что статус `ready` пока недоступен.

## Обновление workflow

В режиме ссылки `main` означает текущую версию, которая может меняться между
чатами. Для стабильного поведения замените `main` в ссылке на выбранный commit SHA;
все references нужно читать из той же ревизии. Сначала проверьте доступность
зафиксированных ссылок в своём ChatGPT.

В режиме снимка соберите новый полный файл из выбранной ревизии GitHub и замените
старый источник проекта. Не оставляйте конфликтующие снимки. SHA-256 в начале
файла помогают сверить исходное содержимое. Переход между режимами задавайте явно;
автоматически подменять недоступную ссылку старым снимком нельзя.

Настройки проекта задают правила, но не гарантируют безошибочное выполнение:
проверьте чтение workflow, реальные Google-инструменты и тестовые записи.
