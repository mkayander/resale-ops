# Браузер и безопасность аккаунта

Для Авито/Юлы в этой версии браузерный инструмент не требуется: пользователь вручную ищет аналоги и размещает подготовленные материалы в штатном сайте/приложении. Агент не подключается к аккаунту. Это уменьшает риск, связанный с автоматизацией, но не гарантирует отсутствие санкций за содержание и другие нарушения правил.

Разрешённые методы и основания описаны в [реестре площадок](../skills/resale-ops/references/platforms.md). Наличие MCP и согласие владельца аккаунта не заменяют разрешения самой площадки.

## Chrome с постоянным профилем

По запросу открыть браузер запускайте установленный Google Chrome с портом
`9222` и отдельным постоянным профилем Resale Ops. Команды для Windows / WSL,
macOS и Linux — в [инструкции запуска](../skills/resale-ops/references/browser.md#persistent-chrome-launch-windows-macos-and-linux).
Встроенный браузер клиента не подставляется вместо Chrome.

| ОС | Папка профиля |
| --- | --- |
| Windows / Windows Chrome из WSL | `%LOCALAPPDATA%\ResaleOps\ChromeProfile` |
| macOS | `~/Library/Application Support/ResaleOps/ChromeProfile` |
| Linux | `${XDG_CONFIG_HOME:-$HOME/.config}/resale-ops/chrome-profile` |

Всегда используйте ту же папку, без TEMP или /tmp. Первый вход выполняется
вручную; данные профиля сохраняются между запусками, но сайт может завершить
сессию. Прежний временный профиль автоматически не переносится, cookies и токены
не копируются. Профиль хранится вне репозитория и архивов плагина.
Сам запуск не разрешает агенту подключение к аккаунту или действия на площадке.

## Разработка будущего разрешённого адаптера

[Playwright MCP](https://github.com/microsoft/playwright-mcp) и [Chrome DevTools MCP](https://github.com/ChromeDevTools/chrome-devtools-mcp) могут читать формы, вводить поля и загружать файлы. Это возможности инструментов, не разрешение использовать их на любом сайте.

Готовый конфиг с `@latest` удалён. После проверки происхождения пакета, версии, зависимостей и схем зафиксируйте конкретную версию. Установку выполните отдельно от запуска браузера с аккаунтом; при обновлении повторите проверку. Сначала тестируйте локальную форму без логина и персональных фото. Не используйте аккаунт владельца для тестирования CAPTCHA, лимитов или поведения антибота.

Для разрешённой работы нужен отдельный профиль задачи, минимальные доступные инструменты и файлы, ручной ввод пароля/2FA и проверка фактического HTTPS hostname после переходов. Приватный профиль не скрывает автоматизацию от площадки и не гарантирует отсутствие блокировки.

Не подключайте весь личный Chrome через CDP, не экспортируйте cookies/storage state, не открывайте отладочный порт в сеть. Отключите ненужные HAR/trace/video, запись сессий и диагностические выгрузки до входа. Проверьте телеметрию сервера; личные сведения не должны попадать в публичный репозиторий.

В Playwright `allowed-origins` не является полноценной границей безопасности и не покрывает перенаправления — это прямо оговорено в [настройках upstream](https://github.com/microsoft/playwright-mcp#configuration). Не полагайтесь на него как на защиту от передачи фото на другой сайт. Если клиент не обеспечивает нужное ограничение доступа, используйте ручной режим.

Локальные файлы должны быть доступны среде инструмента; не пересылайте их на удалённый MCP ради обхода ограничения пути. Перед загрузкой нужны выбранные пользователем копии с проверенными метаданными и видимым содержимым.

## Что считать разрешением

Для каждой операции заранее подтвердите разрешённый площадкой интерфейс, права аккаунта, категорию, стоимость, лимиты и результат. Если официальный импорт сразу публикует объявления, его нельзя использовать как способ сохранения черновика. Встроенный браузер клиента подчиняется тем же условиям, что и MCP.

Подробный [протокол браузера](../skills/resale-ops/references/browser.md) применяется только после допуска метода. В этой версии ни один автоматический адаптер для аккаунтов маркетплейсов не допущен.
