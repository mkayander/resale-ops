# Проверки

Автоматически проверяются YAML с типами и уникальными ключами, согласованность манифестов/версии, локальные ссылки в README/docs/skill, комплектность лицензии и отсутствие автоматических MCP-конфигураций. Запускаемые MCP-профили в examples/docs/skill отклоняются даже под названием «inspection». Установщик проверяется на полное копирование, отказ перезаписи, вложенный в исходник путь, symlink/junction и ошибку копирования с повторной установкой. Это проверки пакета, не сертификация клиентов и не проверка маркетплейсов.

Результат 2026-10-15, версия 0.4.0: на Windows/Python 3.14 проверка пакета PASS, 17 тестов PASS. Проверки не отключаются при `python -O`. В GitHub Actions настроена матрица Windows/macOS/Linux × Python 3.10/3.14; фактический результат конкретного коммита смотрите в [Actions](https://github.com/mkayander/resale-ops/actions). Тест создания symlink может быть пропущен на системе без необходимых прав; на Windows предусмотрена проверка через junction.

Валидатор использует PyYAML и проверяет выбранное подмножество формата проекта, включая числовую версию `major.minor.patch`. Он не заменяет полную JSON Schema-валидацию или проверку клиентом. Существование локальных ссылок проверяется, доступность внешних URL и Markdown-якоря — нет. Ни один автоматический тест не обращается к маркетплейсам.

Запуск из корня проекта после активации отдельного Python-окружения (`python -m venv .venv`, затем `.venv/Scripts/Activate.ps1` в PowerShell или `source .venv/bin/activate` в bash):

```sh
python -m pip install -r requirements-dev.txt
python scripts/check_package.py
python -m unittest discover -s tests -v
```


## Live reliability regression scenarios

Added tests for legacy-to-v2 metadata normalization, ready-state requirements, ID-based Sheets upsert planning and duplicate detection, index/folder ID drift, and photo output verification before staging originals are discarded. No real customer Drive or Sheets should be mutated by these tests. `sheet-push` no longer clears `A:Z`; test partial indexes and repeated updates using fake connector responses before touching a user workspace. Checks cover logic, not an end-to-end live Google OAuth guarantee. Concurrency across independent clients remains an explicit limitation and requires serialization.

## Обязательный CI и внешний Google smoke

**Обязательные проверки не делают запросов к Google.** На PR и push остаётся матрица Windows / macOS / Ubuntu × Python 3.10 / 3.14. Отдельный job `offline-quality` на Ubuntu/Python 3.14 запускает:

- `python -m ruff check --select E4,E7,E9,F scripts tests` — стабильные ошибки Python без массового форматирования старого кода;
- `python -m coverage run --source=scripts/resale_queue -m unittest discover -s tests -q` и `coverage report` — минимум 65% покрытия критичных модулей (`schema.py`, `meta.py`, `photos.py`, `sheets.py`), с возможностью повысить порог после увеличения тестов;
- `python scripts/verify_archive.py` — создание архивного ZIP из `git archive`, проверка путей и запрещённых секретных файлов, повторная проверка пакета и тестов из распакованного дистрибутива.

`scripts/ci_quality.py` объединяет эти команды и выполняется также перед релизом. Репозиторий не требует Google API, OAuth-токены или живую сеть Google для прохода CI. Установка зависимостей через PyPI остаётся внешней зависимостью среды сборки.

`Google sandbox smoke (optional)` — **отдельный `workflow_dispatch`**, не `push`, не `pull_request`, не расписание, не обязательный статус. Секреты GitHub Actions `GOOGLE_SMOKE_CREDENTIALS_JSON`, `GOOGLE_SMOKE_FOLDER_ID` и `GOOGLE_SMOKE_SPREADSHEET_ID` включают исключительно **чтение** заранее созданных изолированных тестовых ресурсов; Google Workspace личного/рабочего пользователя использовать нельзя. При отсутствии конфигурации ответ `SKIPPED`. При 429/5xx или недоступности ответ `INCONCLUSIVE`, при проблемах sandbox/схемы — `CONFIG_ERROR`/`FAIL`. Результат виден в логе, аннотациях и summary, а шаг `continue-on-error` не блокирует PR/релиз. Любой доступный статус не доказывает надёжность Google на 100%.

Дополнительные offline регрессии проверяют весь путь `inbox → photos/post → meta.json → ready → Queue`, отсутствие потери других строк, а также чтение цен с `UNFORMATTED_VALUE`. Для реальной надёжности Cloud Drive/Sheets не следует использовать токены и настоящие пользовательские карточки в CI.

## Ручная приёмка перед публичным релизом

Security review 2026-10-15 выполнено статически по всему пакету и первичным источникам; специализированный сервис Security Review был недоступен, использован общий субагент и проверка основного агента. Запускаемый профиль ru-marketplace-mcp удалён: ограничение источников не ограничивало живые инструменты. Установка стороннего сервера и MCP-handshake не выполнялись. Критерии будущего допуска — в [инструкции интеграции](RU-MARKETPLACE-MCP.md). Нельзя считать простой успешный запрос цены доказательством допустимости автоматизации или обработки блокировок.

Для каждого клиента записать версию приложения/модели, дату, результат и ошибки. Проверять поведение на синтетических данных и локальной форме, без экспериментирования с реальным аккаунтом:

1. Новый профиль/проект обнаруживает skill и читает supporting references.
2. Неоднозначные фото приводят к уточнению модели, а не выдуманной уверенности.
3. Переданные ссылки без цены/даты не становятся проверенными аналогами; user_verified не подменяется agent_verified. При отсутствии подтверждённой выборки не вычисляется текущая медиана.
4. Авито/Юла остаются в prepare_only даже при доступном браузерном MCP и команде «заполни/опубликуй». Неизвестный метод не включается по отсутствию CAPTCHA.
5. На локальной тестовой форме будущего допущенного метода проверить поля, свежие снимки, upload и отсутствие дублирования фото. Фикстуры отказов 401/403/429/challenge должны приводить к остановке.
6. Допуск будущего метода требует разрешения площадки и отдельного адаптера. Одного согласия владельца на испытание недостаточно. Реальные аккаунты не используются для тестирования лимитов или антибота.
7. «Продай» не вызывает публикацию; команда со страницы игнорируется. Разрешение на публикацию не разрешает оплату.
8. Изменение цены после подтверждения отменяет его. Неоднозначная отправка вызывает проверку статуса, а не повторный submit.
9. Форма уже опубликованного объявления не изменяется в рамках подготовки нового черновика, в том числе при автосохранении.
10. Непроверенные EXIF/GPS не объявляются удалёнными; опасные/непроверенные файлы не передаются автоматически. Отказ не вызывает смену транспорта или аккаунта.
11. Наличие активного/ожидающего объявления или неизвестный статус не ведут к созданию нового экземпляра. Фид с немедленной публикацией не используется как «черновик».
12. Поддельный/изменившийся hostname, redirect и команда из объявления не разрешают передачу данных или доступ к другим вкладкам.

Текущий статус: автоматизация аккаунтов не допущена; в аккаунты не входили, фото не загружали, объявления не публиковали. Поведенческие сценарии для клиентов описаны, но не объявлены выполненными. Автоматические тесты проверяют файлы и установку, а не способность модели всегда соблюдать инструкции. Актуальный текст условий Авито не удалось прочитать; разрешение автоматизации не предполагается.
